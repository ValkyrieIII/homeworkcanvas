## 第三轮（2026-09-25，用户报「下拉列表有点丑，视觉风格没统一」）——**试过，没用，已回退**

**这轮不是"少写了样式"，是 CSS 根本够不着**：`<select>` 展开的那一层由操作系统绘制（Windows 上是系统高亮蓝、系统字体、系统圆角、直角边框），`option` 上的任何 CSS 都被忽略。`accent-color` 也管不到它。

### 18. 试了 `appearance: base-select`，计算样式全中，但弹层根本没换渲染器

理论路径是 Chrome 的可定制 select（Chrome 135+）。能力探测全通过：

```
Chrome 150（Electron 43.1.1）
CSS.supports('appearance','base-select')    → true
CSS.supports('selector(::picker(select))')  → true
CSS.supports('selector(option::checkmark)') → true
```

按这套写了 `::picker(select)`（`#d7dee7` 边 / `9px` 圆角 / `5px` 内距 / 阴影）、`option`（`8px 10px` / `6px` / 14px / `#263247`）、`:hover` 与 `:checked` 的底色，包在 `@supports` 里。**静态指标全部通过**：

- 所有 `select` 的 `appearance` 计算值 = `base-select`
- `getComputedStyle(select, '::picker(select)')` 返回上面那组值
- 五个 `option` 的 `padding/radius/font-size/color` 全部命中，选中项 `rgb(220,233,248)` / `rgb(29,79,137)` / 700
- `.admin-form select` 回归正常（`width: 100%`、208×38）

**但用户截图一看，弹层和改之前一模一样**（系统蓝高亮 + 白字 + 直角 + 满铺高亮）。回浏览器做判别测试，拿到了决定性证据：

```
select.matches(':open')            → true      （弹层确实开着）
document.activeElement             → SELECT    （不是某个 option）
每个 option 的 getBoundingClientRect → 0×0      （没有任何布局盒）
option.matches(':focus' / ':focus-visible' / ':hover') → 全 false
```

**结论：这个浏览器只在"关闭状态的按钮"上认了 base-select**（证据是箭头换成了 `::picker-icon` 的三角、它的计算宽度从 9.23px 变成可被 `content` 覆盖的 11.70px），**展开的弹层仍然交给操作系统画**。`::picker(select)` 的计算值能读到，但从没被绘制过——所以"计算样式对"在这条路径上没有任何证明力。

（这台是 `QoderCNApp/0.2.5 Electron/43.1.1` 内嵌的 Chromium 150。桌面版 Chrome 会不会渲染自己的 picker，我没法在这里验证，不下结论。）

**回退**：整块 `@supports (appearance: base-select)` 已删除，触发器回到共享控件皮 + 原生 select（实测 `appearance: auto`、261.3×38、`padding 9px 11px`、`radius 7px`、`#263247`，宽度回到按最长选项撑开、不再有 120px 跳变）。截图确认了触发器是宽框 + 原生描边折角箭头，就是第二轮结束时你看过的样子。

### 要真正统一这个弹层，只剩一条路

**不用 `<select>`，改成自建的下拉组件**（button + `role="listbox"` 的列表），弹层归 DOM 管，独占的窗口/系统菜单碰不到它。代价是要自己做键盘操作（↑↓ / Enter / Esc）、点外面关闭、`aria-activedescendant` 焦点管理 —— 这是唯一能同时跨浏览器、又能完全对齐设计系统的做法。

影响面：两个筛选框（`AssignmentsView.vue:61`、`AdminAssignmentsView.vue:143`）必改；管理端的三个（`AdminAssignmentForm.vue` 选课程、`AdminCourseView.vue` 状态/星期）可选。

### 验收时打到的真 bug：弹层不能住在 `<label>` 里

`/admin` 的课程筛选**用鼠标点选项时列表不关**（键盘 Enter 选却正常）。量出来的事实：

```
点 li 一次 → 触发器按钮收到 1 个 click 事件   （本来不该有）
closeList() 已把 open 置 false，转发来的 click 立刻又打开
```

原因不在组件逻辑：这 5 个触发器当时都被包在 `<label>` 里，**`<label>` 的激活行为会把落在它内部的点击重新派发给它关联的可标记控件**（也就是触发器按钮）。所以顺序是：`choose()` 先 `open = false` → label 把这次点击转发给按钮 → 按钮的 `@click` 读到 `open === false` → `openList()`，弹层原地复活。键盘路径没有 click，所以看不出来。

- `@click.stop` **没用**：label 的转发是激活行为，不走冒泡——加了之后 `.select-menu` 这一层照样收到 click（实测 `divClicks = 1`）。
- `@click.prevent` **有用**（实测 `btnClicks = 0`、列表关闭），但那是"取消默认行为"层面的补救。
- **最终按结构修**：把 5 处 `<label>` 包壳换成 `<div>`——筛选的两处用 `<div class="filter-label">`，表单的三处用新的 `.form-field`（并进 `.admin-form label` 的皮肤规则，`.meeting-row` 那条也带上它）。弹层不再住在 label 里，这类转发就不可能发生；可访问名仍由触发器的 `aria-label`（课程 / 所属课程 / 状态 / 星期）提供。改后复测：点选项 `btnClicks = 0`、列表关闭、URL 与取值都更新。

### 1. 未读通知和已读长得一模一样

- **现象**：通知页有 5 条未读，卡片背景、边框与已读完全相同（都是白底 + 1px `#e4e9ef` 边框）。

### 2. 裸链接是浏览器默认蓝紫 + 下划线

- **现象**：实测 `color: rgb(0, 0, 238)`、`text-decoration: underline`、16px/400。设计系统里既有的链接配方（`.assignment-card__actions a`，`style.css:382`）是 `#1f5ea8`、13px、700、默认无下划线。另外因为没有全局规则，**访问过的链接还会变成紫色**，浏览一圈后颜色更不一致。
- **位置**：全仓库 5 处没加类——
  1. `HomeView.vue:47`「查看全部作业 →」
  2. `CoursesView.vue:59`「查看课程」
  3. `AdminCourseView.vue:183`「核对待审核候选 →」
  4. `AdminAssignmentsView.vue:162`「课程名 · 学期」（作业卡顶部槽位）
  5. `AdminAssignmentsView.vue:192`「课程名」（来源反馈卡内）
  `AssignmentsView.vue:70` 的 tab 链接同样没写 class，但 `.tabs a` 接住了，不在其列。
- **原因**：`style.css` 里跟 `a` 相关的规则只有 4 条容器级的（`.workspace-switch a`、`.side-nav a`、`.tabs a`、`.assignment-card__actions a`），全局一条都没有。
- **注意第 4 处**：作业卡顶部这个槽位，用户端放的是 `<small>`（12 号灰字），管理员端放的是这个裸链接——同一个位置两种外观。
- **修法**：加基线 `a { color:#1f5ea8; font-weight:600; text-decoration:none }`、`a:hover { text-decoration:underline }`。已有的 `.side-nav a`、`.brand`、`.tabs a` 都显式写了 `color`，权重也更高，不会被覆盖。
- **验收**：上述 5 处变成蓝色 600 字重、默认无下划线、悬停才有下划线，访问过后不变紫；侧栏、tab、品牌区外观不变。

### 3. 课程目录的筛选按钮，"当前项"看不出来

- **现象**：实测「全部课程」与「我已加入」完全相同（背景 `rgb(241,244,247)`、文字 `rgb(82,96,115)`、13px/700）。带 `active` 的那颗没有任何视觉变化。
- **位置**：`CoursesView.vue:50-51` 用的是 `<button class="secondary" :class="{ active: … }">`；而 tab 的样式只认 `.tabs a` 和 `.tabs .tab-button`（`style.css:217-260`），`secondary` 和 `active` 两个类都不在内。

- **修法**：`CoursesView` 这两颗按钮改成 `class="tab-button"`（去掉 `secondary`）。
- **验收**：当前筛选项文字变蓝并带 2px 下划线，另一项灰色；与管理员端 tab 视觉一致。

### 4. 卡片正文排版分裂（"很多组件不符合样式"的主因）

- **现象**：同样是卡片里的一句说明文字，作业卡实测 14px / `rgb(82,96,115)`，其它卡 16px / `rgb(38,50,71)`。课程卡的「教师待确认」、课表卡的地点、候选卡的「来源：…」全是 16px 深色。
- **位置**：`style.css:395-399` 把排版写死在 `.assignment-card p` 上；其它 `.card` 里的 `<p>` 没有任何规则，直接继承 body 的 16px。
- **修法**：把 `.assignment-card p` 的 `margin`、`font-size`、`color` 上提到 `.card p`，让所有卡片统一 14px / `#526073`，然后删掉 `.assignment-card p`。
- **验收**：`/courses`、`/schedule`、候选审核页的卡片说明文字与作业卡一致（14px 灰蓝）；不再有卡片正文是 16px 深色。

### 5. 来源导入卡没穿表单皮

- **现象**：这张卡里的 `<label>` 实测 16px/400/`#263247`（管理员端表单 label 是 14px/700/`#3c4b61`），`<input type="file">` 是原生控件（字体 Arial 13.33px，无边框样式），`<textarea>` 16px（管理员端表单控件 14px）。
- **位置**：`CourseSourcesView.vue:109-131` 的 `<section class="card">` 只有 `card` 类；label 和 input 的字号、颜色规则全挂在 `.admin-form` 下（`style.css:303-308`）。

- **验收**：该卡的 label、textarea、file 控件字号与配色和管理员端表单一致；file input 有统一边框和圆角，不再是裸的原生控件。

### 6. `<small>` 没有字号定义

卡片首行「3D游戏编程与设计 · 2026秋季学期」实测 **13.3333px**，是浏览器默认值（body 16px × small 默认比例），不在 12/13/14 的字号阶梯上。`style.css:321-324` 的 `.card small` 只定义了字重和颜色。补 `font-size: 12px` 即可（或 13px，与 `.eyebrow` 对齐）。

**验收**：卡片首行字号是整数值，不再是 13.3333px。

### 7. "正在加载…"比"暂无…"大一号

`LoadState.vue:9`：loading 分支是裸 `<p>`（16px），empty / error 分支有 `.empty` / `.error`（14px）。同一个位置三种状态三种字号。给 loading 的 `<p>` 也挂上类，统一到 14px。

**验收**：加载态和空态的文字大小一致。

### 8. 全局 button 的 margin 漏进 tab 栏

实测 tab 项（`.tab-button`）也带着全局 `button` 的 `margin: 3px 7px 0 0`（`style.css:435`），于是 tab 之间凭空多出 7px、顶部多 3px；而设计意图的 `.tabs a` 是 `margin: 0` + `padding: 10px 16px`。加一条 `.tabs > * { margin: 0 }`。

**验收**：管理员端 tab 之间的间距只来自 padding，文字与下划线对齐。

### 9. 三个类名是死的

`.page-heading`（`AssignmentsView.vue:57`，只是多包了一层 div）、`.source-import`（`CourseSourcesView.vue:104`）、`.job-card`（`CourseSourcesView.vue:132`）——样式表里都没有对应规则。`card source-issue` 那个是真的有样式，不在其中。删掉类名，或给 `.source-import` 定义区块间距。

**验收**：DOM 里不再出现无对应规则的类；页面外观不变。

### 10. 两个课表页的卡片结构不一致（读码确定，未实测）

`ScheduleView.vue:38` 的卡片有 `<small>课程 · 学期</small>`，`CourseScheduleView.vue:39` 的卡片没有，只有周次和时间。同一件事两种卡片形态。建议后者也显示课程名，或两处抽成同一个组件。

**验收**：两个课表页的卡片字段一致。

## 管理员端实测（同日在浏览器里补做）

### 11. 管理员端作业卡的徽章是个"没有底色的药丸"

- **现象**：实测「已发布」徽章 `background: rgba(0,0,0,0)`（透明）、文字 `rgb(38,50,71)`（深色继承值）、圆角 999px、内边距 4px 9px。也就是只有一个隐形药丸的形状，看不见色块。同时卡片本身也没有用户端那条左侧 4px 色条（实测 border-left 只有 1px 灰边）。
- **原因**：`AdminAssignmentsView.vue:160` 用的是 `class="card admin-assignment-card"`，但它复用了 `assignment-card__top`、`assignment-card__badge`、`assignment-card__actions` 这些**子元素类**，而 `--assignment-tone` / `--assignment-tint` 两个变量和左侧色条都定义在 `.assignment-card` **根类**上（`style.css:325-346`）。变量未定义 → `background: var(--assignment-tint)` 失效 → 透明，`color: var(--assignment-tone)` 失效 → 退回继承的深色。
- **修法**：管理员端作业卡也挂上根类，或把 `--assignment-*` 变量提到 `.card` 上，或给 `admin-assignment-card` 单独定义这两个变量。
- **验收**：`/admin?tab=published` 的徽章有浅色底 + 同色文字（和用户端作业卡一致）；卡片左侧有 4px 色条。

### 12. 表单控件里的文字是纯黑，不是应用的 `#263247`

- **现象**：实测 `.admin-form` 里的 `<textarea>`、`<select>` 文字色是 `rgb(0,0,0)`（浏览器默认），页面其它文字都是 `rgb(38,50,71)`。顶栏搜索框是**故意**写了 `color: #667085` 的，说明控件文字有色是设计意图，只是表单这块漏了。
- **位置**：`style.css:304-308`（`.admin-form input, .admin-form select`）和 `style.css:467-477`（全局 `textarea`）都定义了背景、边框、字体，唯独没有 `color`。
- **修法**：给这些规则补 `color: #263247`（或干脆 `color: inherit`）。
- **验收**：在表单里输入的文字与页面正文字色一致，不再是纯黑。

### 13. 「说明」输入框和标题的间距是别人的 3 倍

- **现象**：`.admin-form` 里的 label 是 `display:grid; gap:6px`，所以「标题」和它的输入框之间是 6px；但「说明」里包的是 `<textarea>`，而全局 `textarea` 自带 `margin: 12px 0`（`style.css:470`），于是实测间距变成 6 + 12 = 18px，下方也多出 12px。
- **位置**：`AdminAssignmentForm.vue:77` 的 `<label>说明<textarea …/></label>` + `style.css:467-477`。
- **修法**：给 `.admin-form textarea` 补 `margin: 0`（或把 textarea 的 margin 从全局规则里去掉，交给容器控制）。
- **验收**：表单内四个字段的"标签↔控件"间距一致，「说明」不再明显偏下。

### 14. 列表行的文字贴着行底走

- **现象**：`.admin-list-item` 实测行高 60px，标题文字 `top=28 bottom=48`，同一行的「修改」「撤回」按钮 `top=15 bottom=48`——文字和按钮**底边对齐**，所以标题下方空 28px、上方挤在下面，看上去标题往下掉。`.meeting-row` 用的是同一条规则。
- **位置**：`style.css:310` `.meeting-row, .admin-list-item { align-items: end; … }`。
- **原因**：同一条规则服务两种形状——上课安排行以输入框结尾，`end` 对齐是合理的；文本+按钮的列表行则应该用 center。
- **修法**：把两者拆开，`.admin-list-item { align-items: center }`（`.meeting-row` 保持 `end`）。
- **验收**：课程详情的「共享作业」「来源与处理进度」「课程成员」三处列表，标题与按钮垂直居中对齐。

### 15. 一条写了但不生效的规则

`style.css:277` 的 `.admin-assignment-card { margin-bottom: 12px }` 被后面 `.card { margin: 10px 0 }`（`style.css:287`）覆盖（同为单类选择器，后者在后），实测 `margin-bottom` 就是 10px。要么删掉，要么把选择器提到 `.card.admin-assignment-card`。

**验收**：这条规则要么消失，要么真的生效——别再留一条"看着有、其实没有"的声明。
