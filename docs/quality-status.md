# 当前质量基线（2026-09-23）

## 已有验证

- Go 单元测试覆盖：候选证据必须有原文且页码匹配、中文截止日期边界、模型输入字符预算、模型 HTTP 成功及失败响应、请求日志与异常恢复的信息边界。
- PostgreSQL 集成测试覆盖：文字来源处理成功、证据无效时的状态流转；含老师文字的 PDF 与文字一起进入抽取器；编辑候选后发布以及清空官方截止时间。测试在同一事务中创建临时 schema，结束时回滚；只有显式设置 `TEST_DATABASE_URL` 才执行。
- 前端目前只有类型检查和构建检查，没有自动化交互测试。
- API 与 Worker 的日志为 JSON。API 每个请求有 `X-Request-ID`，记录路由模板、状态和耗时；Worker 记录 `job_id`、阶段、尝试次数、页数、候选数和错误码。日志不记录请求正文、原始页面、模型密钥和完整 URL。

本机执行：

~~~powershell
Set-Location backend
go test ./...
go vet ./...
go build ./...

# 使用专门的 PostgreSQL 测试连接串运行隔离 schema 集成测试
$env:TEST_DATABASE_URL='postgres://...'
go test ./internal/ingestion ./internal/assignments -count=1

Set-Location ../frontend
npm run build
~~~

## 仍需处理的风险

1. **身份与部署边界。** 当前请求头身份适配器仅适合本地开发；真实 UniSSO 验证尚未接入。不能把当前 API 直接作为可信生产服务。
2. **关键业务测试不足。** 候选审核并发、通知事务、个人状态更新、成员权限和浏览器交互尚无自动化回归覆盖。已有一条小型 PDF 解析集成路径，但不覆盖复杂文档。现有测试不能证明整个系统可靠。
3. **摄入异常路径。** 模型错误仍不分可重试与不可重试；文件转换共用超时预算，预览会生成但没有消费者；部分早期上传清理路径仍忽略删除错误。长文档截断只写入日志，审核者尚不知道遗漏页面。
4. **人工审核证据。** 审核页已展示文字摘录和页码，但原文件及页面预览会在处理后删除；维护者仍需结合原始通知自行核对复杂版面。
5. **接口一致性。** 部分 PATCH/PUT 可能覆盖未提交字段；分页和显式 `Idempotency-Key` 尚未实现。文件按同一课程、同一上传者的内容校验值去重，文字来源尚未去重。
6. **运行监测。** 当前只有结构化日志和任务状态；没有指标、告警、追踪，也没有覆盖 PostgreSQL 与 Redis 的就绪检查。`/healthz` 只说明 HTTP 进程能响应。

更细的读码发现及其证据见 [后端审查报告](review-backend-2026-09-23.md)。其中早先的“零测试/零结构化日志”描述应以本文件为当前基线；未标为已修复的业务问题仍需逐项核验。
